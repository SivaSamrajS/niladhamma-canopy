# Niladhamma, rebuilt on Canopy

A static rebuild of [niladhamma.co.in](https://www.niladhamma.co.in) (a Blogger
site) using **Canopy**, the CultureMonkey Platform design system. 224 pages, 112
in each language, no framework, no build toolchain beyond one Python script.

Paths are root-relative, so serve from the project root. The pages will not
resolve over `file://`.

```
python3 build.py              # regenerate all 224 pages + sitemap + robots
python3 -m http.server 8347   # then open http://localhost:8347
```

Every page of the original was read before anything was written: the eight

## தம்மபதம்: முப்பத்தோர் நாள்

Parsed out of `நிலா_தம்மக்கதை_ஜூலை (1).docx`. The document is regularly
structured, so `data/stories.json` was extracted programmatically: day marker,
title, body paragraphs, தம்மக்கருத்து, அம்பேத்கர் இணைப்பு, ஆதாரம். All 31 days
came through complete, with no manual patching.

The docx also carries 16 hand-drawn medallions (cream ground, terracotta rim,
line-icon subject). They are reused as the story identity: a circle on the index
grid, a 104px plate on the story page. They land exactly on Canopy's preference
for a tinted icon panel over stock photography, so the story pages carry no
photographs at all.

Each story page has breadcrumbs, prev and next, an aside linking back to the
collection and out to Events, and `Article` structured data carrying its source
citation.

## Brand mark

The mark is the sangha's own Ashoka Chakra: a navy disc with the wheel cut out
in white. It is masked to a circle at build time rather than keyed to
transparency, because the spokes *are* the white ground; keying white out would
hollow them. The circular badge reads correctly on the light topbar and on the
dark footer without a plate behind it.

The mark keeps its navy rather than being recoloured to Canopy green. A brand
mark is identity, not chrome, so it sits outside the token set on purpose.

To regenerate every size from a source image:

```
python3 tools/make_icons.py path/to/logo.jpg
```

The lockup is mark, then the Tamil name at 19px/700, then the romanised name as
a tracked eyebrow behind a short green rule. The rule is what stops the second
line reading as a redundant repeat of the first.

## Cover image

`hero-buddha-dusk.jpg`: a Buddha profile silhouetted against a dusk sky with the
light behind it (Borobudur, CC BY 2.0, credited in `CREDITS.md`).

The scrim is directional rather than a flat wash: heavy on the left where the
copy sits, clearing to four percent on the right so the silhouette and the light
stay visible. That is the whole reason the cover reads as a photograph rather
than as a dark rectangle.

Contrast was measured, not assumed. The photo and both gradient layers were
composited to a canvas and sampled under the actual glyph runs of every text
block:

| Element | Desktop | Mobile | Needs |
| --- | --- | --- | --- |
| Quote 44/30px 700 | 14.8:1 | 12.0:1 | 3:1 |
| Eyebrow 11px 700 | 10.8:1 | 10.0:1 | 4.5:1 |
| Attribution 15px | 11.4:1 | 8.1:1 | 4.5:1 |
| Lede 16px | 7.7:1 | 6.7:1 | 4.5:1 |

Below 1080px the copy spans the full width, so the side-lit scrim cannot keep it
off the bright sky. The mobile block swaps in a full vertical wash. If you
change the photo, re-check these numbers; a brighter sky on the left will break
the eyebrow first.

**Resolution caveat.** The logo source supplied was 48x48 (the YouTube channel
avatar), which is exactly right for the favicon but has no headroom above it.
The topbar mark is served at 96px for a 32px slot, so it is crisp on retina;
`logo-192.png` and `apple-touch-icon.png` are upscaled and are noticeably soft
at full size. If a larger original exists, re-run `tools/make_icons.py` against
it and everything downstream sharpens with no other change.

`assets/css/canopy.css` is a straight copy of the Canopy dev-handoff bundle. It
carries the tokens and the `.cm-*` component classes. Never edit it; if Canopy
ships a new build, replace the file.

## Canopy rules observed

- **Border-first elevation.** Cards are a 1px `#e3e8e4` border at `radius-lg`,
  no shadow. Shadows would mean "floats above the page".
- **Key-lines** are a 2px inner `border-bottom` (section heads, primary
  buttons), never a drop shadow.
- **Focus ring** is 2.5px `green.800` with a 2px offset gap, never suppressed.
- **Semantic tokens only.** `nila.css` reads `--cm-text-*`, `--cm-action-*`,
  `--cm-border-*`, `--cm-accent-wash`. No raw hex except the dark footer and
  the hero scrim, which are outside the token set by design.
- **Motion** is functional: 120ms hover, 180ms state, 240ms panels, and
  `prefers-reduced-motion` collapses it.
- **No em-dash anywhere.** Middot for inline meta, en-dash only inside quoted
  source examples.
- **No emoji, no unicode-as-icon.** Icons are inline SVG at 1.8 stroke with
  round caps, Lucide-equivalent shapes, recoloured with `currentColor`.
- **Status pairs colour with an icon and copy.** The certificate page's success
  panel is green plus a check plus a sentence, never colour alone.
- **Violet is reserved for AI** and therefore appears nowhere on this site.
- **Employee register**: 16px reading text, 48px controls, centred column,
  desktop and mobile.

## Surface system

Canopy's default ground is `--cm-bg-app: #ffffff`, which left every page, card
and menu on the same white sheet. The system does sanction a tinted field: the
employee survey puts a colour field behind a card "to make the survey feel like
a calm, separate space". That idiom is applied site-wide here.

| role | value | used for |
| --- | --- | --- |
| field | `#e4ebe6` | the page itself |
| surface | `neutral.25` `#fbfcfb` | cards, bands, chrome, overlays, reading sheets |
| well | `neutral.100` `#eef1ef` | recessed areas inside a surface, hover states, table heads |
| tint | `green.50` `#eef5ee` | accented panels and bands |

Two Canopy semantic tokens are retuned rather than overridden per component, so
every `.cm-*` primitive follows without being restyled:

- `--cm-bg-app` moves to `neutral.25`. Card, menu, modal, input, secondary
  button and segmented control all leave pure white together.
- `--cm-text-muted` steps one notch darker, to `#5e6961`. Canopy sets
  `neutral.600` and measures it at 5.0:1 against white; on the tinted field it
  is 4.29:1, under AA. The re-paired value clears 4.5:1 on every ground used
  here (field 4.72, well 5.03, tint 5.16, surface 5.57) and stays visibly
  lighter than body text. Canopy's warning is against going lighter than
  `neutral.600`, never darker.

Separation is still done by the 1px border; nothing in flow floats. The one
overlay on the site, the mobile navigation menu, takes elevation 2 as Canopy
requires of an overlay.

`--nd-field` is the one value to move if the page should read lighter or
heavier. `#e0e7e2` is the floor: past it the re-paired muted text drops under
4.5:1 and the text colour would have to move again with it.

Verified in the browser rather than by inspection: zero pure-white surfaces
across 18 pages in both languages, and zero contrast failures over every text
run measured against its actually painted background, with tab panels revealed,
long lists expanded and the mobile menu open, at 1280px and 390px. The hero is
measured separately by compositing photograph and scrim.

## Archive posts

The 64 posts arrive as Blogger markup: loose divs, runs of `<br>`, empty
paragraphs left behind by the editor, and every photograph wrapped in a
one-cell table whose second row is the caption, usually empty. That was being
shipped as-is, which drew hairlines where the empty caption cells sat and left
each picture at whatever width the editor happened to save.

`parse_body()` now reads each body once into blocks:

    ("p",   inline html)
    ("ul",  [inline html, ...])
    ("fig", src, caption)

and the page is composed from those. The Tamil original is the only thing
parsed; the English page reuses its figures and interleaves them with the
translated paragraphs, each picture keeping the share of the post it sat at in
the original. Only prose is rewritten, never the pictures or their order.

**Photograph layout.** Every archive image is a local file, so its true pixel
size is known at build time. That one fact does the work:

- `width` and `height` on every `img`, so the page does not reflow as the
  photographs arrive
- a run of photographs is packed into justified rows, a picture desk's
  arrangement: each row fills the width and the aspect ratios decide who gets
  how much of it. Nothing is cropped
- widths are emitted as `flex-grow`, not pixels, so a packing computed against
  748px holds its proportions at every screen size. Only the first picture in a
  row declares a height; the rest stretch to it
- a short last row is centred and held to the common height by grown spacers
  either side
- below 640px the packing is dropped and each photograph takes the full width
  at its own ratio
- a captioned photograph stands alone, because a caption needs a line to itself

**Display copies.** `assets/img/pathivu/tile/` holds a 720px copy of each
photograph, written by `build.py` on the first run and left alone afterwards.
The originals average a quarter of a megabyte, and a post with eight pictures
paid that eight times. The full file is still what the viewer opens, and is
still the `srcset` candidate at large sizes. Delete the directory to
regenerate. Without Pillow installed the originals are used and the pages are
heavier, but the build does not fail.

**The viewer** is the one overlay on the site, so it is the one place Canopy
allows a shadow. Every photograph is already a link to its full file, so
scripting only intercepts the click: with JavaScript off the link opens the
picture, which is the honest fallback. Arrow keys move, Escape closes, focus is
trapped while it is open and returns to the photograph that opened it.

**Page furniture.** The article sits in a centred 812px sheet rather than a
left-aligned column, since a post page carries no sidebar to balance it. Text
keeps a 640px measure inside a sheet cut for photographs at 748px. The head
carries date, reading time, photograph count and a copy-link control; the
opening paragraph is set as a standfirst.

## Documented deviations

Four, each deliberate:

0. **No drop cap on story pages.** `::first-letter` splits a Tamil grapheme
   cluster, separating a base consonant from its vowel sign, so the opening word
   renders broken. The opening paragraph is set slightly larger instead.

1. **Tamil typeface.** Canopy is Figtree-only, and Figtree has no Tamil
   coverage. The stack is `'Figtree', 'Noto Sans Tamil', system-ui`, so Latin
   renders in Figtree and Tamil falls through to Noto Sans Tamil at the same
   four weights (400/500/600/700). Tamil line-height is raised to 1.75 because
   Figtree's Latin metrics are too tight for the script.

2. **Photographic imagery.** Canopy favours tinted icon panels over photography
   and keeps photos out of chrome. This is a cultural site, so photography
   carries real meaning here. The compromise: chrome (topbar, nav, cards,
   tables, footer) stays photograph-free and Canopy-clean; imagery appears only
   in content surfaces (hero, feature panels, media cards, gallery, sidebar
   plates).

3. **Title Case.** Canopy's Title Case rule is explicitly English-reference
   only, so Tamil navigation and headings keep Tamil convention. English
   secondary labels ("Buddhist Names", "Community Certificate") are Title Cased.

## SEO and AEO

- **Per page**: unique title and meta description (verified no duplicates
  across every page), canonical URL, `robots` with `max-image-preview:large`,
  Open Graph and Twitter card with a page-appropriate image, `lang="ta"`.
- **Structured data**, all validated as parseable JSON:
  41 `BreadcrumbList`, 31 `Article`, 5 `FAQPage`, 3 `CollectionPage`,
  1 each of `Organization`, `WebSite`, `AboutPage`, `ContactPage`, `HowTo`.
  The Organization node is referenced by `@id` from every other node rather
  than repeated.
- **AEO**: the FAQ blocks are real visible content, not collapsed panels, so
  the question is an `h3` and the answer sits directly under it as prose. The
  certificate page is marked up as `HowTo` because it genuinely is a procedure.
  Answers are written to stand alone when quoted out of context.
- **Crawl**: `sitemap.xml` (42 URLs, priorities and change frequency by page
  type), `robots.txt` pointing at it, `404.html` set to `noindex, follow`.
- **Verified**: 0 broken internal links, 0 missing assets, 0 JSON-LD parse
  errors, 0 images without `alt`, exactly one `h1` per page, no heading-level
  skips. Re-run the checks in the "Validation" section below after edits.

`BASE` at the top of `build.py` sets the canonical origin. It is
`https://www.niladhamma.co.in`. Change it before deploying anywhere else, or
every canonical and every absolute URL in the structured data will point at the
old Blogger site.

## The writers' desk

`/write/` (and `/en/write/`) is where members sign in with the shared username
and password and publish a post: title, sub-heading, author, date, tags, a body
with headings, bold, italic, links, quotations and lists, photographs, and
YouTube videos. It is linked from the footer and is `noindex`.

The site stays static. Publishing is a commit:

```
assets/js/write.js            the editor; sends blocks, not HTML
netlify/functions/write-*.mjs sign-in, and list / read / publish / withdraw
netlify/lib/write.mjs         sessions, sanitising, the GitHub commit
data/blog/<date>-<id>.json    one file per member post, written by the function
assets/img/pathivu/m*.jpg     its photographs, with tile/ and thumb/ copies
```

A publish writes the post and its photographs in one commit through the GitHub
API. That push starts the normal Netlify build, and `build.py` renders the post
with the same page, photograph rows and viewer as the archive. A post is live
about two minutes after Publish is pressed. Editing rewrites the same file;
withdrawing deletes it and its photographs.

Photographs are reduced in the browser to 1800px, plus the 720px display copy
and the 480 by 360 card thumbnail the archive keeps, because the deploy host
has no Pillow to make them. Their pixel sizes travel in the post file for the
same reason. Video is a YouTube link, embedded from `youtube-nocookie.com`.

Settings live in Netlify (Site configuration > Environment variables), never in
the repository:

| Variable | Value |
| --- | --- |
| `WRITER_USERNAME` | the shared sign-in name |
| `WRITER_PASSWORD` | the shared password |
| `WRITER_GITHUB_TOKEN` | a fine-grained GitHub token for this repository only, with Contents set to read and write |

Changing the username or the password signs every writer out, since sessions
are signed with a key derived from both. A redeploy is needed for a changed
variable to reach the functions.

Three things are deliberate:

- **Text is reduced twice.** The function keeps only `b`, `i`, `u`, `br` and
  `https` or `mailto` links, and `build.py` applies the same rule again when it
  renders, so a file edited by hand cannot put markup on a page.
- **A post cannot break the deploy.** The audit fails a build on a repeated
  title or description, a skipped heading level, an `http://` link or a missing
  image. Each of those is normalised in `build.py`, and a malformed file in
  `data/blog/` is skipped with a line in the build log.
- **Posts are published at once.** Anyone holding the password can put a post
  on the public site. There is no approval queue.

## Known gaps

- **Download links are not wired.** The original page's file links were not
  reachable from the feed, so `downloads.html` has the structure and the
  metadata but no href targets yet.
- **Event photos are hotlinked** to `blogger.googleusercontent.com`. Some 2018
  and 2021 posts no longer resolve there; `site.js` substitutes a local plate.
  Mirror the photos into `assets/img/` before this goes live.
- **Post pages are not rebuilt.** Cards on `writings.html` and `events.html`
  link out to the existing Blogger posts, so those 64 URLs are outbound rather
  than indexed here. `data/posts.json` already holds the full text, so
  rebuilding them locally the way the stories were done is the obvious next
  step and the single biggest remaining SEO win.
- **No `Event` structured data.** The sangha meets every full moon, but there
  are no published future dates to cite, and inventing them would be worse than
  omitting the markup.
- **Social handles** for Instagram, YouTube and X are taken from the site
  banner graphic; verify the URLs resolve before publishing.
